# Connecting OCP VM Nodes to a Containerlab Fabric via dev-scripts

This documents how we connect OpenShift VMs (provisioned by dev-scripts) to a
containerlab EVPN fabric for OpenPerOuter E2E testing.

---

## 1. dev-scripts Configuration

The key feature is `EXTRA_NETWORK_NAMES` in dev-scripts `config_root.sh`:

```bash
export EXTRA_NETWORK_NAMES="toswitch1 toswitch2"
export TOSWITCH1_NETWORK_SUBNET_V4='192.168.11.0/24'
export TOSWITCH2_NETWORK_SUBNET_V4='192.168.12.0/24'
```

This tells dev-scripts to:
1. Create two libvirt networks (`toswitch1`, `toswitch2`) with their own bridges
2. Attach an extra NIC to **every VM** (masters + workers) on each network
3. The NICs are provisioned at VM creation time (no hot-plug)

After `make` completes, each VM has 4 NICs:
- `ens2` (provisioning bridge)
- `ens3` (baremetal bridge `ostestbm` at 192.168.111.0/24)
- `ens4` (toswitch1 bridge at 192.168.11.0/24) 
- `ens5` (toswitch2 bridge at 192.168.12.0/24)

The kernel names (`ens4`, `ens5`) vary by PCI slot. We rename them to
`toswitch1`/`toswitch2` using udev rules (see step 7 in `setup-clab.sh`).

### Verifying the extra NICs

```bash
# Check the libvirt networks exist
virsh net-list
# toswitch1   active
# toswitch2   active

# Check bridge names (should match the network names)
virsh net-info toswitch1 | grep Bridge
# Bridge: toswitch1

# Check a VM has NICs on the extra bridges
virsh domiflist ostest_worker_0
# vnet42   bridge   ostestpr    virtio   ...
# vnet43   bridge   ostestbm    virtio   ...
# vnet44   bridge   toswitch1   virtio   ...  <-- extra NIC
# vnet45   bridge   toswitch2   virtio   ...  <-- extra NIC
```

## 2. Containerlab Topology

The clab topology (`clab/singlecluster/ocp.clab.yml`) wires the fabric to
the OCP nodes via the libvirt bridges. The key difference from the kind
topology: no `ext-container` nodes, no kind bridge switches. Instead, clab
uses the libvirt bridges directly.

```yaml
# ocp.clab.yml (relevant parts)
name: kind
topology:
  nodes:
    # Standard fabric: leafA, leafB, spine, hosts (same as kind)
    leafkind1:
      group: frr
    leafkind2:
      group: frr

    # Bridge nodes reference the PRE-EXISTING libvirt bridges
    toswitch1:
      kind: bridge    # <-- uses existing Linux bridge, doesn't create one
    toswitch2:
      kind: bridge

  links:
    # leafkind connects to the libvirt bridges via clab veths
    - endpoints: ["leafkind1:eth2", "toswitch1:lk1"]
    - endpoints: ["leafkind2:eth2", "toswitch2:lk2"]
    
    # Standard fabric links (spine, leafA, leafB, hosts)
    - endpoints: ["leafkind1:eth1", "spine:eth3"]
    - endpoints: ["leafkind2:eth1", "spine:eth4"]
    # ... etc
```

### How the wiring works

```
OCP VM (master-0)                     containerlab
  toswitch1 NIC ──── libvirt bridge ──── lk1 veth ──── leafkind1 (FRR)
    (virtio)         "toswitch1"          (clab)         eth2
```

The `kind: bridge` node type tells clab to use an existing Linux bridge
rather than creating one. Clab creates a veth pair (`lk1 ↔ eth2`) and
enslaves `lk1` to the bridge. The VM's virtio NIC is already on the same
bridge (placed by libvirt). Result: L2 connectivity between the VM and
the leafkind FRR container.

This is functionally identical to kind's setup where clab creates its own
bridge (`leafkind1-sw`) and both the kind node and the leafkind container
connect to it.

## 3. NIC Management on OCP Nodes

### NIC Renaming

The VMs' extra NICs get kernel-assigned names (e.g., `enp3s0`) based on
PCI slot. The OpenPerOuter Underlay CR references them by name
(`toswitch1`, `toswitch2`). We rename via udev rules:

```bash
# From setup-clab.sh step 7
BRIDGE_MAC=$(virsh domiflist ostest_worker_0 | grep toswitch1 | awk '{print $5}')
# Inside the node:
echo "SUBSYSTEM==\"net\", ATTR{address}==\"${BRIDGE_MAC}\", NAME=\"toswitch1\"" \
    > /etc/udev/rules.d/70-toswitch1.rules
udevadm control --reload-rules
ip link set enp3s0 name toswitch1
```

The udev rules persist across netns transitions (OpenPerOuter moves NICs
between the host netns and the perouter netns).

### Static IP Assignment

DHCP is disabled on the toswitch networks (setup-clab.sh removes the DHCP
section from the libvirt network XML). Static IPs are assigned
deterministically:

```
toswitch1:  192.168.11.100 + node_index   (master-0=.100, master-1=.101, ...)
toswitch2:  192.168.12.100 + node_index
```

These IPs survive netns transitions because the OpenPerOuter controller
captures and re-applies them when moving NICs between namespaces.

### NetworkManager

NM is disabled for toswitch NICs (`nmcli device set toswitch1 managed no`)
to prevent it from interfering during netns transitions.

## 4. IP Addressing and Topology Config

The test suite consumes a `topology.json` that describes how cluster nodes
connect to the fabric. This file is generated by `setup-clab.sh`:

```json
{
  "nodes": {
    "master-0": {"peerLeafIP": "192.168.11.100"},
    "master-1": {"peerLeafIP": "192.168.11.101"},
    "master-2": {"peerLeafIP": "192.168.11.102"},
    "worker-0": {"peerLeafIP": "192.168.11.103"},
    "worker-1": {"peerLeafIP": "192.168.11.104"}
  },
  "peerLeaf1IP": "192.168.11.2",
  "peerLeaf2IP": "192.168.12.2",
  "underlayNics": ["toswitch1", "toswitch2"],
  "underlayNeighbors": [
    {"asn": 64512, "address": "192.168.11.2"},
    {"asn": 64513, "address": "192.168.12.2"}
  ]
}
```

The test reads this file via `--infra-config` flag and configures the
Underlay CR accordingly. Same topology file format works for kind
(with different IPs).

## 5. Bootstrap and Recovery

### Bootstrap Underlay

The FRR container in the router pod waits up to 60 seconds for the
perouter network namespace to exist. The perouter netns is created by the
controller when an Underlay CR exists. Without a bootstrap Underlay, FRR
times out and crashes.

`setup-clab.sh` creates a bootstrap Underlay CR so the controller creates
perouter and FRR starts healthy. The test suite's `BeforeSuite` manages
the Underlay lifecycle from there.

### NIC Recovery Monitor

`recover-toswitch.sh` is the OCP equivalent of kind's `check_veths`. When
a test deletes an Underlay CR, the controller leaves NICs in the perouter
netns with group ID 0 (released). The monitor detects this and:

1. Moves NICs back to the host netns
2. Re-assigns their static IPs (using `ip addr replace` from topology.json)

This ensures NICs are ready for the next test's Underlay creation.

## 6. Running E2E Tests

```bash
# After OCP + OpenPerOuter operator are deployed:
export KUBECONFIG=/root/dev-scripts/ocp/ostest/auth/kubeconfig

# Set up the clab fabric and wire to OCP
./openshift/e2e/setup-clab.sh

# Run tests
cd e2etests
CONTAINER_RUNTIME=podman go test -v ./suite/ \
  --infra-config=../openshift/e2e/topology.json \
  --frrk8s-namespace=openshift-frr-k8s \
  -ginkgo.v -ginkgo.focus="for single stack ipv4"

# Tear down
cd ..
./openshift/e2e/teardown-clab.sh
```

`CONTAINER_RUNTIME=podman` is required because the test executor uses
podman to exec into clab containers (leafA, leafB, etc.) for FRR config
changes. OCP servers don't have docker.

| `SUMMARY_CI.md` | Summary of all code changes for infra-agnostic E2E |

### dev-scripts config additions

The only dev-scripts configuration needed beyond the defaults:

```bash
# In config_root.sh
export EXTRA_NETWORK_NAMES="toswitch1 toswitch2"
export TOSWITCH1_NETWORK_SUBNET_V4='192.168.11.0/24'
export TOSWITCH2_NETWORK_SUBNET_V4='192.168.12.0/24'
```

Everything else (bridge creation, NIC attachment, network configuration)
is handled automatically by dev-scripts.
